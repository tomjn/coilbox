# The Coilbox hub

The Coilbox hub is a website where players share what they make in coilbox: singleplayer presets, challenges, setup packs, scenarios, base blueprints and unit tweak projects. Coilbox has its own page for the hub, so you can find something and import it without opening a browser.

Browsing and importing need no account. To share something, you sign in to the hub with Discord.

Open it from Library > Community in the sidebar.

## The Coilbox hub page

Each card shows a picture, a title, what kind of thing it is, the date it was shared and the start of its description. Under that are the game, the map, who shared it and its tags.

To narrow the list:

- Type in the search box to search titles and descriptions. Press / to jump to the box.
- Pick a game in Game or a map in Map. The lists hold the games and maps you have installed, and you can type any other name.
- Select one or more kinds, such as Scenarios or Base blueprints. All shows every kind again.
- Select the game, the map, the name or a tag on a card to show only things that share it.

Each filter you set appears as a button above the cards. Select it to take that filter off, or select Clear all to take them all off.

The list that says Newest first changes the order. The other choice is Title.

The number beside the kinds says how many things match. Previous and Next at the bottom move between pages.

A card for something you already imported says Imported and has an Open button. Open goes straight to your copy.

The buttons at the top right are:

- Share, which shares a setup pack or your maps and games. See [Share a setup pack](#share-a-setup-pack) and [Share your maps and games](#share-your-maps-and-games).
- Sign in with Discord, which signs you in to the hub. Once you are signed in, your name is there instead.
- Hub website, which opens the hub in your browser.

## An item's page

Select a card to open its page. The page shows:

- the kind, the title and who shared it on which date
- the whole description
- what is inside it, such as a drawing of a blueprint's buildings or a challenge's map
- the game and the map it is for, and its tags

Coilbox hub at the top left goes back to the list.

Under the details are:

- Import, which brings it into coilbox. See [Import something](#import-something).
- Copy link, which copies the address of its page on the hub website, ready to send to somebody.
- View on the hub, which opens that page in your browser.

## Import something

1. Open the item's page.
2. Select Import.

Coilbox opens the page where that kind of thing lives, with the item ready to add:

| Kind | Where it opens |
| --- | --- |
| Singleplayer preset | Play > Singleplayer |
| Conquest challenge | Play > Conquest |
| Warpath challenge | Play > Warpath |
| Setup pack | Library > Maps |
| Scenario | Play > Scenarios |
| Base blueprint | Library > Blueprints |
| Unit tweak project | Unit tweaks, which needs Unit tools turned on in Settings > General |

If it needs a game or a map you do not have, coilbox offers to download it before it saves anything.

When the page has a warning about the item, the button says Import anyway. Read the warning first. It may say the item was made for a newer version of coilbox, or that it is not the kind of thing the hub lists it as.

For blueprints and scenarios, see [Import a blueprint from the hub](blueprints.md#from-the-hub) and [Import a scenario somebody shared](campaigns-and-scenarios.md#import-a-scenario-somebody-shared).

To find presets from the Singleplayer page, open the presets drawer with the bookmark button at the top and select Browse the hub. The hub page opens showing only singleplayer presets.

### Remove something you imported

The page of something you imported has Open and Remove instead of Import.

1. Select Remove.
2. Select Delete to confirm.

This deletes your copy on this computer. It stays on the hub, so you can import it again.

## Share your own

You need to be signed in to publish. Select Sign in with Discord on the Coilbox hub page or in the share drawer. A browser window opens, and you finish signing in there.

Most things are shared from the same kind of drawer. It has Copy code, Copy link and Export as file at the top, and Publish to the Coilbox hub at the bottom.

1. Type a title. This is what people see first.
2. Add a description and some tags, separated by commas, if you want to. Both are optional.
3. Select Publish.

Coilbox says Published to the Coilbox hub and shows the address of its page. Copy link copies that address, and View on the hub opens it.

If you are not signed in, the drawer offers Sign in with Discord, and Copy code & open hub. The second copies the code and opens the hub website, where you can finish publishing in your browser.

Where the Share button is for each kind:

| Kind | Where to find Share |
| --- | --- |
| Conquest challenge | The share button on a conquest's card on the Conquest page |
| Warpath challenge | The share button on a run's card on the Warpath page |
| Scenario | Share in a scenario's menu in Campaign builder > Scenarios, or in the menu at the top of the scenario editor |
| Base blueprint | Share on a blueprint's page. See [Publish to the hub](blueprints.md#publish-to-the-hub) |
| Unit tweak project | Share in a project's menu on the Unit tweaks page |
| Setup pack | Share, then Share a pack, on the Coilbox hub page |

Campaign builder is in the sidebar once Mission builders is turned on in Settings > General, and Unit tweaks once Unit tools is.

A scenario must name a game and a map before you can publish it. Something too large for the hub cannot be published, and the drawer says so in place of the form.

### Share a preset

A singleplayer preset has no Publish button of its own. To put presets on the hub, include them in a setup pack.

### Share a setup pack

A setup pack is a list of games and maps, and can carry some of your presets too. Whoever imports it gets the games and maps offered as downloads.

1. On the Coilbox hub page, select Share, then Share a pack.
2. Give the pack a name.
3. Tick the games and maps it should hold.
4. Under Presets (optional), tick any presets to include.
5. Select Create pack code.

The drawer then shows the code, with Publish to the Coilbox hub under it.

## What is sent to the hub

When you publish something, coilbox sends the hub:

- the thing itself, the same code that Copy code gives you
- the title, description and tags you typed
- your hub account, so your Discord name shows as the person who shared it

Anyone browsing the hub can see and import it.

When you import something from the hub, coilbox tells the hub that the item was imported, so the hub can count imports. That message says only which item it was. It has no account and nothing that points back to you.

When coilbox finishes downloading a map or a game, it tells the hub which one, so the hub can count downloads. This happens for every finished download, including ones coilbox starts for you, such as a map a lobby needs. It has no account and nothing that points back to you. Engine downloads send nothing.

When you select Look for a track on the hub on a replay's page, coilbox sends the hub the replay's game id, a number that identifies the match. It has no account. Opening the page sends nothing. See [Download a recorded track](#download-a-recorded-track).

Coilbox also asks the hub about a map by its name, to show facts about maps you have not installed. If a map file you download is not what the hub lists for it, coilbox sends the hub a report of the difference.

Coilbox sends nothing about your own games, maps, presets, replays or other files unless you publish them, turn on the sharing in [Share your maps and games](#share-your-maps-and-games), or send a replay as [Send replays to the hub](#send-replays-to-the-hub) describes.

Signing out only affects this computer. It does not remove anything you have already shared.

## Share your maps and games

The hub shows pictures and facts about maps and games next to the things people share. You can help fill these in from your own installed games and maps.

Open it from Share, then Share your maps and games on the Coilbox hub page, or from Settings > Coilbox hub. Both show the same controls.

Sending pictures to the hub is off unless you turn it on. Turn on Send pictures of your games and maps to the hub to allow it. Read the text above the switch first. What you send is public and hard to take back, and the pictures are made from other people's games and maps. They go to the hub under your account, with your name on them.

Once it is on, four buttons appear:

- Send what your maps say sends measurements of each map, such as its size, its height range, its wind and tidal power and where players start. It sends no pictures and no files.
- Send pictures of your maps sends the minimap of each map.
- Send what your games say sends the names of each game's units, what each one builds and which faction it belongs to. It sends no pictures and no files. It skips games in a loose folder.
- Send pictures of your games sends each unit's icon and pictures of its model. Pick one game or All games first.

The two picture buttons share an hourly allowance with every other player, so a big collection takes several presses. Each press picks up where the last one stopped.

With the switch on, opening a blueprint's page also sends pictures of the buildings in it that the hub does not have yet.

## Send replays to the hub

You can put the replay of a match you were in on the hub, so other people can download it. You send one replay at a time from its page, or turn on a setting that sends each match when it ends.

Replays on the hub are public. Anyone can download one and see the players, the build orders and the totals. The hub notes that you sent it, under your lobby name.

### Send one replay

The Send to hub button is at the top of a replay's page, beside Watch. See [Open a replay](replays.md#open-a-replay). It is only there when:

- you are signed in to the hub
- you played in the match or watched it, under a lobby name you have signed in to coilbox with

A remix has no Send to hub button.

1. Select Send to hub. Coilbox reads the replay, which can take a moment.
2. Read the box that says Send this replay to the hub?
3. Select Send.

While it goes, the button says Sending to hub…, then The hub is checking it… while the hub looks over what it received. Once the hub has kept it, the button says On the hub. Select it to open the replay's page on the hub website.

If somebody else who was in the match sent it first, the hub already has it. Coilbox uploads nothing, and the button says On the hub and links to their copy. The hub notes that you sent it too.

Once coilbox has seen a replay on the hub, the replay's page says On the hub from the start, and the replay carries an On hub badge on the Replays page.

### When a replay is not sent

If the hub refuses a replay, the button says Not sent. Select it to see why. Where trying again could help, for example when no mirror could take the file or the connection dropped, there is a Send again button.

The hub also checks each replay after it arrives. If the check refuses it, the box says why, for example that the replay stops before the match ended. There is a Send again button when the file did not arrive as it was sent, or the hub could not finish its check. If the upload ran out of time, the box says that instead.

If a moderator has taken the replay down, the button says Taken down from the hub and cannot be selected. Coilbox does not send that replay to that hub again.

A hub that cannot give a reason only lets coilbox say that it did not keep the replay.

Sometimes coilbox cannot read what the hub needs from the replay, and the box says so in place of Send. The most common reasons are:

- The recording stops before the end of the match. The hub only takes a whole match.
- The game the match was played on is not installed, or another version of it is. Install the version it was played on, then try again.

### Send a replay's analysis and track

Once the hub has a replay, you can also send it what coilbox found when it played the match again, and the match's recorded track for replay rewind. See [Analyse a replay](replays.md#analyse-a-replay). Anyone who was in the match can send these, whoever sent the replay.

A Send analysis button appears beside On the hub when the replay has an analysis that played out exactly as the match did. A run that did not is never sent.

1. Select Send analysis.
2. The button says The hub is checking the analysis… while the hub compares it with the replay. Coilbox asks the hub how it went every 10 seconds while the page is open.
3. Once the hub has passed the analysis, the button says Send track if the replay has an up to date recording. Select it.
4. The button says Sending track…, then The hub is checking the track…, then Track on the hub.

The button also offers Send track when the hub has a track from an older version of coilbox's recorder and you record the match again with a newer one. The hub puts the new track in the old one's place once it has checked it. If the hub cannot replace its track yet, the button says Track not sent, and you can try again later.

If the hub refuses the analysis, the button says Analysis refused. Select it to see why. Coilbox does not offer the track then.

If the track is not sent, the button says Track not sent. Select it to see why. Where trying again could help, for example when someone else is sending a track of the same match, there is a Send again button.

Sending the same analysis twice does nothing new. The hub answers with what it made of the first one.

### Download a recorded track

Recording a replay for [replay rewind](replay-rewind.md) means playing the whole match again. If somebody has already sent the match's track to the hub, you can download it instead. You do not need to sign in, and you do not need to have been in the match.

1. Open the replay's page and go to the Analysis and recording section.
2. Select Look for a track on the hub. It is there when the replay has no up to date recording.
3. If the hub has one, the button to record is replaced by Download the hub's track, with the file's size. Select it.

The replay then has Watch with rewind and the Recorded match section, as if you had recorded it yourself. A download makes no analysis. You can still select Analyse this replay.

Coilbox checks that the file is the one the hub described before keeping it, and throws it away if not. A downloaded track counts towards the [disk space for tracks](replay-rewind.md#disk-space).

The page says the hub has no track when nobody has sent one, when the hub is still checking the one it was sent, when the place it is kept cannot be reached, and when it came from another version of the recorder than yours.

A distribution that turns recording off has no Look for a track on the hub button.

### Send your finished matches automatically

Settings > Coilbox hub has Send my finished matches to the hub, under Replays. It is off until you turn it on. See [Settings](#settings).

With it on, when a match ends coilbox sends its replay if:

- you played in it or watched it
- there were people on two or more sides, so a game against AIs only is not sent
- it reached game over

It sends nothing until you are signed in to the hub. A match that ended while you were signed out waits, and goes if you sign in within a week of it.

If the hub or a mirror cannot take a replay, coilbox tries again later, waiting longer each time. It keeps trying for a week after the match. If the hub refuses the replay, or the week runs out, coilbox tells you the replay was not sent and why.

With the setting on, coilbox also sends a match's analysis, then its track, when you analyse and record it. It waits until the hub has the replay. If the hub is still checking the analysis, coilbox asks again every minute, and sends the track once the analysis has passed. If the hub cannot replace an older track yet, coilbox says nothing and asks again when you next analyse and record that match. A match you analysed before turning the setting on is not sent by itself. Use the buttons on its page.

Turning the setting off forgets every replay, analysis and track still waiting to be sent, and stops one that is being sent.

### What a sent replay holds

When you send a replay, coilbox sends the hub:

- the replay file
- a summary of the match: the game, map and engine, when it was played and how long it lasted
- the players, their teams and the faction each one picked, and the spectators
- who won, and each team's totals
- where each player started
- each player's build orders, with the list of units in them and what each unit costs
- your hub account and the lobby name you were in the match under

When you send an analysis, coilbox sends the version of coilbox's analysis it came from and the list of events it recorded, such as each unit made, given and lost, and the final totals. It leaves out the list of unit types the game has, which coilbox keeps apart.

When you send a track, coilbox sends the track file exactly as it was recorded, which holds where every unit was during the match, and your hub account.

## Settings

Settings > Coilbox hub has:

- Your hub account, with Sign in with Discord or Sign out
- the controls in [Share your maps and games](#share-your-maps-and-games)
- Send my finished matches to the hub, under Replays. See [Send your finished matches automatically](#send-your-finished-matches-automatically)

Which hub coilbox uses is in Settings, then Library > Sources. It shows the hub address coilbox is using. Type in Your hub address to point coilbox at a different hub. Leave it blank to use the default. Clear override puts it back.

You can also reach it from the Coilbox hub page. Select your name at the top right, then Account and sharing settings. Sign out is in the same menu.
