- https://github.com/tomjn/coilbox/issues/1587 : the passworded room, merged as https://github.com/tomjn/coilbox/pull/1589. The agent could not reproduce the reported failure at any level and said so rather than inventing a cause: a keyed `OPENBATTLE` opens a battle in unit tests, on a socket against the real client, and in the app across four starts. What it found instead is why nobody could tell what went wrong. The room silently dropped anything a socket sent before its login was applied, `OPENBATTLE` included, which lands the host exactly where the report describes, and over loopback the login wins that race nearly every time. `mp_open_battle` answered when the line was queued rather than when the battle existed. - https://github.com/tomjn/coilbox/issues/1590 and https://github.com/tomjn/coilbox/issues/1591 : the host that waits to be logged in, merged as https://github.com/tomjn/coilbox/pull/1592. - https://github.com/tomjn/coilbox/issues/1566 : the UDP beacon, merged as https://github.com/tomjn/coilbox/pull/1594. One line per datagram, `coilbox-room/1 {json}`, with the magic and version outside the JSON so a listener decides whether a beacon is meant for it before parsing, and `tcpdump` can name it undecoded. Adding a field never moves the version, because unknown fields are ignored and missing ones default, so the version only moves when a field changes meaning. The payload deliberately carries no address: the one to dial is the datagram's source address, which is right for the interface it arrived on, and a host with a LAN and a VPN cannot know which of its own addresses reached you. Group 239.255.8.250 on UDP 8250, inside the RFC 2365 local scope so routers do not carry it off the network. Neither side picks an interface: the sender transmits from every local address it can find, to both the group and the limited broadcast, because multicast and broadcast get dropped in different places. A host sees its own room marked rather than filtered out, because a host who cannot see their own room has no way to tell whether anyone else can. Proved on CI's Linux runner rather than only this Mac: two listeners bound to one port both hear a beacon, which fails outright without the address reuse, and a room driven over a real socket through login and `OPENBATTLE` reads back with the right title, game, map, count and password flag. A room now announces this machine's private address instead of loopback. Not driven in the GUI. The interface list is probed through the routing table rather than enumerated, which is why https://github.com/tomjn/coilbox/issues/1595 exists.

Found by driving it: splitting `host:port` on every keystroke moved the caret between fields mid-type, so `127.0.0.1:8300` landed as `127.0.0.1300` on port 8. The address is now read rather than rewritten and only settles into the two fields on blur.

- https://github.com/tomjn/coilbox/issues/1571 : approve, reject and kick, merged as https://github.com/tomjn/coilbox/pull/1598. The prompt sits in the battle room under the header, not on the Battles page, because starting a room lands the host in the battle room and that is where they are when somebody knocks. It is also the only banner on that page with a person blocked on the other end of it. A kick blocks a name for the life of the room, not a socket, which a reconnect replaces, and not an address, which a router makes meaningless. - https://github.com/tomjn/coilbox/issues/1568 and https://github.com/tomjn/coilbox/issues/1569 : reachability, merged as https://github.com/tomjn/coilbox/pull/1601. Both ports are mapped or neither: a method that opens the lobby port but not the engine's is rolled back and the next one tried, because getting everyone into a room that then cannot start is the failure the issue names. NAT-PMP is tried before UPnP, for leases rather than speed, and if both fail the host gets manual instructions with both port numbers and the LAN address. Four STUN servers from four operators, rotated to a different starting index each run, so one being down costs a 1.5 second timeout rather than the answer and no single operator sees every coilbox host's public address. Nine candidates were probed and five rejected, one for answering without the attribute. Leases are an hour, renewed every thirty minutes, permanent only when a router says it supports nothing else. Mappings are released when the room stops, when the toggle is cleared and when the ports change, but a killed app releases nothing, which is https://github.com/tomjn/coilbox/issues/1603. The toggle is off by default in both places, because opening a port changes what the rest of the internet can reach and the LAN case needs none of it. **A successful mapping has never run on real hardware**: this router refuses UPnP, NAT-PMP and PCP, so what was proved here is the failure path, driven in the app on both host paths. The ignored tests in `crates/tauri-plugin-coilbox-direct/tests/reachability.rs` are there for someone with UPnP switched on.

- https://github.com/tomjn/coilbox/issues/1613 : mDNS and DNS-SD, merged as https://github.com/tomjn/coilbox/pull/1621. Rooms now announce as `_coilbox-room._tcp.local.` beside the existing beacon, which is untouched, so an older coilbox still finds a newer one. `mdns-sd` was chosen over `zeroconf` and `astro-dnssd` because it is a responder in its own right rather than a wrapper round Bonjour or Avahi, so it needs no system library on any of the three platforms. The two sources merge on the room id, carried in the TXT record, because the DNS-SD instance name is the room title and gets renamed when two rooms share one. When they disagree the beacon wins, and not because it is ours: a beacon's age is bounded at two seconds by construction, while a DNS-SD record is sent once and served from caches afterwards, so its arrival says nothing about how old the player count in it is. They expire on separate clocks for the same reason, seven seconds against a goodbye or a 150 second backstop, since sharing one would flicker an mDNS-only room out every seven seconds. One advertise switch governs both, because announcing on a second channel after somebody turned announcements off is the opposite of what they asked for. Checked independently of our own code with `dns-sd -B` and `dns-sd -L` from a terminal, including confirming that a room with advertising off publishes nothing, and that a gracefully stopped room sends a goodbye while a killed one ages out by TTL about 60 seconds later.
